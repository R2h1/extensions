> 更新日期：2026-08-17。基于当前代码库真实状态（闲页已瘦身、书搭子为 demo、conan.js.cn 为功能中枢）。

## 1. 战略定位

- **闲页 = 个人启动台**：保留"本地个人化"功能（天气、微信读书、摸鱼工资、日历、壁纸、喝水…），聚合类重功能逐步外移到 conan.js.cn。扩展保持**轻、快、稳**。
- **conan.js.cn = 功能中枢 & 全栈主战场**：工具箱/行情/热搜等重功能都放这里，是练"补后端 + AI 全栈"的主阵地。
- **书搭子 = 独立小产品**：从 demo 走向真实可用的"读书笔记社区"，是打通"读书记录 → 分享 → AI 复盘"闭环的关键。

---

## 2. 分阶段路线

### Phase 1 — 网站补全 + 闲页稳定（≈ 1 个月）

**conan.js.cn**
- ✅ `/market` 落地页：指数 / 自选 / 行业板块 / 黄金，红涨绿跌、移动端友好（已完成）
- ✅ `/hot` 落地页：微博 / B站 / 百度 / 掘金 热搜聚合（已完成）
- [ ] 顶部 dock 三个入口（工具箱 / 行情 / 热搜）落地页全部可用的验收（行情/热搜已可用，待实际点开复核）

**闲页**
- [ ] 近期重构引入的变化全面手验（面板渲染 / 设置保存 / 微信读书 / 壁纸 / 锁屏 / 媒体）
- [ ] 性能与首屏：壁纸 / APlayer 懒加载、可选暗色模式
- ✅ 已定：聚合类数据卡（资讯 / 社区 / 云平台 / 翻译）**保留现状**，不再外移

**书搭子**
- [ ] 确定 BaaS 方案（Supabase 优先）与数据模型（书 / 笔记 / 摘录 / 书评 / 点赞 / 用户）

**里程碑**：外链入口都有高质量落地页（行情/热搜✅）；闲页零回归；书搭子有可执行的后端方案。

### Phase 2 — 书搭子 MVP 成真（2–4 个月）

- [ ] **后端（BaaS）**：Supabase 认证、笔记/摘录/书评 CRUD、点赞、跨设备同步
- [ ] **扩展侧**：真实数据接入替换 mock；**侧边栏快速摘录**（选中网页文本 → 存书 / 存笔记），这是书搭子的核心交互
- [ ] **网站侧**：书搭子配套落地页 / 内容页
- [ ] **闲页**：如需要，把书搭子入口接到 dock

**里程碑**：真实用户可注册、跨设备同步、社区有真实内容流。（BaaS 方案上手快，"补后端"重心转向数据建模/RLS 策略/前后端联调）

### Phase 3 — 数据 & AI 进阶（4–8 个月）

- [ ] **书搭子 AI 读书助手**：划词解释、内容摘要、全书问答（RAG）
- [ ] **conan.js.cn**：AI 工具补全（对齐"AI 全栈"目标，如 Agent 工作流、RAG 工具）
- [ ] **闲页**：网站统计跨日趋势、番茄钟月度复盘、微信读书年度报告联动

**里程碑**：AI 能力成为书搭子的差异化卖点。→ 达成"AI 全栈"能力目标。

### Phase 4 — 生态打通（8–12 个月）

- [ ] 三端账号打通：闲页偏好 ↔ 书搭子 ↔ conan.js.cn
- [ ] 阅读数据统一：微信读书 + 书搭子笔记 + 网站书单/榜单
- [ ] 内容沉淀：读书笔记整理成周刊 / 博客 / 开源，形成个人品牌

**里程碑**：形成"阅读 → 记录 → 分享 → AI 复盘"闭环，产品矩阵互相引流。

## 3. 已定决策（2026-08-17 拍板）

| 决策点 | 结论 |
|---|---|
| 闲页瘦身程度 | **保留现状**：资讯/社区/云平台/翻译等聚合卡不再外移 |
| 书搭子后端 | **用 BaaS**：Supabase 优先，快速上线 MVP |
| 书搭子目标用户 | **先自用可展示**：本人可用 + 可放进简历/开源，再考虑开放 |
| 节奏 | **暂不执行**：当前仅作规划文档，按个人学习节奏再启动 |
